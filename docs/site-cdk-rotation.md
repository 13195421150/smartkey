# 本站卡密换新

后台 `/ops/cdkeys` 中，未使用卡密右侧的「操作」菜单提供「卡密换新」。确认后该行显示新码，可复制新码发给顾客。

换新只修改本站卡密：卡台原始 CDK、对应 ID、套餐、备注、充值任务、任务状态、失败原因和使用状态都保留。新码继续映射到同一张卡台 CDK，不调用卡台发码或停用接口。

Plus、Pro5x、Pro20x 分别保持 `PLUS-`、`Pro5X-`、`Pro20X-` 前缀。换新后旧本站码和该记录原 ZC- 码在本站失效；卡台官网的原始码不受本站换码影响。

旧兑换会话同时失效。新码验证会获得新的本站会话；即使卡台复用令牌，也不会恢复旧本站会话的权限。

操作前会实时核对卡台未使用状态和兑换记录。处理中的任务、未确认结果、接口异常或记录不完整时会拒绝换新，请先核对原订单。相同操作重试返回相同新码，过期列表请求会被拒绝。

重新同步不会覆盖本站新码；列表、搜索、复制和导出使用当前映射。不会重写原有任务、Session 绑定和失败诊断记录。

原 `/partner/swap`、`/a/swap` 及 `/api/v1/public/cdk/exchange` 已关闭并返回 HTTP 410，原代理密码配置已移除。

## 更新与回退

先备份 SQLite，再部署前后端。启动时自动添加本站映射、退役码和会话表，不需要手动导入业务库存。

产生换码记录后，不能直接降级到不识别这些映射的旧程序，否则旧码会重新被接受。修复与升级时应保留这三张表及映射解析能力。

当前部署为单进程 Go 服务，换码与兑换通过同码锁和 SQLite 事务互斥；扩展到多实例时须先实现跨实例的同等互斥保护。
